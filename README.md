# eval-agent

인사담당자가 자연어로 질문하면, LLM 에이전트가 필요한 도구를 스스로 골라 평가 데이터를 조회하고 근거와 함께 답하는 서비스. (Python + LangGraph + MCP)

> 예: "2025년 영업본부 B등급 비율이 왜 다른 본부보다 높아?"

## 왜 만드는가

이 프로젝트의 목적은 두 가지다.

1. **직접 만들어 보며 익히기**: Java/Spring 백엔드 개발자로서 실무 경험이 없는 Python, 그리고 LangGraph와 MCP로 AI 에이전트를 처음부터 끝까지 직접 구현해 본다.
2. **설계 이유까지 설명할 수 있는 포트폴리오**: 동작하는 코드뿐 아니라 "왜 이렇게 설계했는가"를 설명할 수 있도록, 각 단계의 설계 결정과 한계를 기록한다.

### 이전 프로젝트와의 차이

이전에 Spring AI로 평가 문의 자동 분류 시스템을 만들었다. 그 시스템은 **정해진 순서대로 도는 워크플로**였다. 이번에는 **LLM이 어떤 도구를 부를지 직접 선택하는 에이전트 구조**로 만들어, 두 방식의 차이를 직접 비교하고 설명할 수 있게 하는 것이 목표다.

## 설계 원칙

- **도구는 자유 SQL을 받지 않는다.** 정해진 파라미터만 받는 읽기 전용 함수로 만들어, LLM이 DB를 마음대로 조회하거나 변경할 수 없게 한다.
- **도구를 먼저 만들고 검증한 뒤 에이전트에 연결한다.** 도구는 순수 함수로 만들어 pytest로 검증한다.
- **도구로 확인한 숫자만 사실로 말한다.** 데이터에 없는 원인은 추측하지 않고 "추가 확인이 필요합니다"라고 답한다. 답변 끝에는 어떤 도구를 어떤 조건으로 호출했는지 근거를 붙인다.
- **개인 이름은 노출하지 않는다.** 집계 결과만 다룬다.
- **실제 고객사 데이터를 쓰지 않는다.** 모든 데이터는 시드 스크립트가 만드는 더미 데이터다.

## 진행 단계

| 단계 | 내용 | 상태 |
|------|------|------|
| 1 | 프로젝트 구조 + uv 환경 + docker-compose(PostgreSQL) | 완료 |
| 2 | 스키마 + 더미 데이터 시드 스크립트 | 완료 |
| 3 | 도구 4개 + pytest | 완료 |
| 4 | LangGraph 에이전트 + CLI | 완료 |
| 5 | FastAPI 엔드포인트 `POST /ask` | 구현 완료 (실제 Claude로 호출 검증 진행 중) |
| 6 | MCP 서버 (Claude Desktop/Claude Code에서 도구 사용) | 예정 |
| 7 | README 정리: 구조 그림, 설계 결정과 이유, 한계와 다음 단계 | 예정 |

README의 상세 설계 설명은 7단계에서 정리한다. 아래는 단계별 실행 방법이다.

## 1단계: 환경 준비

내 PC에서 DB와 파이썬 환경이 정상적으로 갖춰졌는지 확인하는 절차다.

```bash
cp .env.example .env                       # 설정 파일 생성 (.env는 커밋되지 않음)
docker compose up -d                       # PostgreSQL 컨테이너 기동
uv sync                                    # Python 3.12 가상환경 + 의존성 설치
uv run python scripts/check_db.py          # DB 접속 확인
uv run pytest                              # 테스트 실행
```

| 명령 | 하는 일 |
|------|---------|
| `cp .env.example .env` | 견본(`.env.example`)으로 실제 설정 파일을 만든다. DB 접속 정보와 API 키 같은 비밀값을 여기에 둔다. |
| `docker compose up -d` | `docker-compose.yml`대로 PostgreSQL 16 컨테이너를 백그라운드로 띄운다. 데이터는 Docker 볼륨에 저장되어 컨테이너를 껐다 켜도 남는다. |
| `uv sync` | `pyproject.toml`과 `uv.lock`대로 프로젝트 전용 가상환경(`.venv`)을 만들고 라이브러리를 설치한다. Python 3.12가 없으면 uv가 받아 온다. |
| `uv run python scripts/check_db.py` | `.env`의 `DATABASE_URL`로 DB에 접속해 `SELECT version()`을 실행한다. `DB 연결 성공: PostgreSQL 16...`이 나오면 정상이다. |
| `uv run pytest` | `tests/` 아래 테스트를 모두 실행한다. |

Docker 데몬이 꺼져 있으면 `Cannot connect to the Docker daemon` 오류가 난다. Docker Desktop을 먼저 실행한다.

## 2단계: 스키마 + 더미 데이터

```bash
uv run python scripts/seed.py            # 테이블 생성 + 더미 데이터 입력 (이미 있으면 중단)
uv run python scripts/seed.py --reset    # 전체 삭제 후 재생성 ('yes' 입력 필요)
```

- 모든 데이터는 가짜이며, 같은 seed로 항상 같은 결과가 나온다.
- 영업본부는 2025년 B등급 비율이 약 68%로 일부러 높게 만들었다.

## 3단계: 도구 4개

모든 도구는 정해진 파라미터만 받는 읽기 전용 함수이고, 개인 이름 없이 집계만 돌려준다. 조회가 안 되면 예외 대신 `{"error": ...}`를 돌려줘서 LLM이 "데이터가 없다"고 답할 수 있게 한다.

| 도구 | 파라미터 | 결과 |
|------|----------|------|
| `get_grade_distribution` | year, org_name?, eval_type? | 등급별 인원·비율, 하위 조직별 breakdown |
| `compare_years` | org_name, year_from, year_to | 두 연도 분포와 등급별 변화(%p) |
| `get_org_summary` | year, org_name | 인원수, 평균 점수, 평가유형별 평균 |
| `search_policy_docs` | query, top_k? | 기준 문서에서 관련 문단 (키워드 검색) |

```bash
uv run pytest        # DB 없이 메모리 SQLite로 도구를 검증한다
```

## 4단계: LangGraph 에이전트 + CLI

LLM이 3단계 도구 중 필요한 것을 스스로 골라 호출하고, 결과를 보고 다시 판단해서 최종 답변을 만든다.

### 준비

`.env`에 발급받은 API 키와 모델명을 넣는다. (`.env`는 커밋되지 않는다. 키를 `.env.example`이나 코드에 넣지 않는다.)

```
ANTHROPIC_API_KEY=발급받은_키
ANTHROPIC_MODEL=claude-haiku-5-5      # 개발 중에는 저렴한 모델로 시작
AGENT_MAX_ITERATIONS=6                # 도구 호출 반복 상한 (무한 루프·비용 폭주 방지)
AGENT_MAX_TOKENS=2048                 # LLM 답변 한 번의 최대 길이 (너무 작으면 답변이 잘린다)
```

### 실행

```bash
uv run python scripts/ask.py "2025년 본부별 B등급 비율을 비교해줘"
uv run python scripts/ask.py -v "개발본부 다면평가 평균은?"    # -v: 도구 호출과 결과를 단계별로 출력
uv run python scripts/ask.py                                    # 질문 없이 실행하면 대화형
```

질문마다 독립적으로 실행되며 이전 질문을 기억하지 않는다.

### 그래프 흐름

```
                 ┌──────────── 도구 호출 요청 있음 & 한도 미만 ───────────┐
                 ▼                                                        │
    START → [agent] ──┬── 도구 호출 요청 없음 ──→ [finalize] → END         │
                      ├── 도구 호출 요청 있음 & 한도 도달 → [limit] → END   │
                      └───────────────→ [tools] ───────────────────────────┘
```

- `agent`: LLM을 한 번 호출한다. LLM은 도구 호출을 요청하거나 최종 답변을 한다.
- `tools`: 요청된 도구를 실행하고 결과를 상태에 쌓는다.
- `finalize`: 최종 답변 뒤에 **실제 호출 기록에서 뽑은 근거**(어떤 도구를 어떤 조건으로 불렀는지)를 코드로 붙인다.
- `limit`: 반복 한도에 도달하면 "추가 확인이 필요합니다"와 함께 멈춘다.

### 설계 결정

- **근거는 LLM이 아니라 코드가 붙인다.** LLM은 호출하지 않은 도구를 호출했다고 쓰거나 조건을 틀리게 쓸 수 있다. 호출 기록에서 뽑으면 사실만 남는다.
- **반복 한도는 그래프 안에서 처리한다.** 한도에 도달하면 예외로 죽지 않고 안내 문구와 지금까지의 호출 기록을 돌려준다.
- **LLM을 밖에서 주입한다.** `build_graph(llm, ...)`가 LLM을 인자로 받아서, 테스트에서는 정해진 응답을 내는 가짜 LLM으로 그래프 배선을 검증한다.
- **조회 가능한 연도는 프롬프트에 DB 값을 넣는다.** "작년", "올해" 같은 상대 표현을 코드에 박힌 연도 없이 해석하게 한다.
- **`AGENT_MAX_TOKENS`로 답변 길이(비용) 상한을 둔다.** 처음에 1024로 두었더니 기준 문서와 데이터를 함께 설명하는 긴 답변이 문장 중간에 잘렸다. 기본값을 2048로 올리고, 프롬프트에서 간결하게 쓰도록 하고, 그래도 잘리면 `stop_reason`을 보고 답변에 "잘렸습니다" 안내를 붙인다.
- **`temperature`는 보내지 않는다.** 일부 최신 모델이 이 파라미터를 거절해서(400 오류) 제거했다. 그래서 같은 질문에도 답변 표현이 달라질 수 있다.

### 테스트

```bash
uv run pytest        # 가짜 LLM으로 그래프 흐름·반복 한도·근거 첨부를 검증한다 (API 호출 없음, 비용 없음)
```

가짜 LLM으로는 그래프의 배선만 검증할 수 있다. 실제 Claude가 도구를 알맞게 고르는지, 답변 규칙을 지키는지는 CLI로 테스트 질문을 던져 확인한다.

## 5단계: FastAPI `POST /ask`

에이전트를 HTTP API로 감싼다. 서버가 시작될 때 에이전트(LLM 클라이언트, DB 연결 풀, 컴파일된 그래프)를 한 번만 만들고 요청마다 재사용한다.

### 실행

```bash
uv run uvicorn eval_agent.api.app:app --host 127.0.0.1 --port 8000
```

- API 문서(Swagger UI): http://127.0.0.1:8000/docs
- 주의: 이 API는 호출할 때마다 Claude API 비용이 든다. **인증이 없으므로 외부에 공개하지 않는다.** 기본 설정(127.0.0.1)은 내 PC에서만 접속된다.

### 호출 예시

```bash
curl -s -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "개발본부 다면평가 평균은?"}'
```

응답:

```json
{
  "answer": "개발본부 2025년 다면평가 평균은 76.66점입니다. ...\n\n근거(호출한 도구와 조건):\n- get_org_summary(year=2025, org_name='개발본부')",
  "tool_calls": [
    {"name": "get_org_summary", "args": {"year": 2025, "org_name": "개발본부"}, "error": null}
  ],
  "iterations": 2
}
```

| 엔드포인트 | 설명 |
|------------|------|
| `POST /ask` | 질문(1~500자)을 받아 답변, 도구 호출 목록, LLM 호출 횟수를 돌려준다. |
| `GET /health` | 서버 상태 확인 |

| 상태 코드 | 의미 |
|-----------|------|
| 200 | 정상 |
| 422 | 입력 오류 (질문 없음, 공백뿐, 500자 초과). LLM을 호출하지 않는다. |
| 502 | LLM 호출 실패. 원인(API 키 오류 등)은 서버 로그에만 남고 응답에는 노출하지 않는다. |

### 설계 결정

- **에이전트는 서버 시작 때 한 번 만든다.** 요청마다 만들면 DB 연결 풀과 LLM 클라이언트를 매번 새로 만들게 된다. 설정이 잘못됐으면(API 키 없음 등) 요청이 들어온 뒤가 아니라 서버 시작 단계에서 바로 실패한다.
- **엔드포인트는 `async def`가 아니라 `def`로 만든다.** 에이전트가 동기(블로킹) 코드라서, `async def` 안에서 호출하면 이벤트 루프가 막혀 서버 전체가 그동안 멈춘다. `def`면 FastAPI가 스레드 풀에서 실행한다.
- **입력 길이에 상한(500자)을 둔다.** 호출마다 비용이 드는 API이므로 비용이 큰 입력을 앞단에서 막는다.
- **오류 원인은 응답에 노출하지 않는다.** 내부 예외 메시지에는 API 키 오류나 내부 구조가 담길 수 있어서 로그에만 남긴다.
- **`create_app(agent=...)`로 에이전트를 주입할 수 있다.** 테스트에서는 가짜 에이전트나 가짜 LLM을 꽂는다.

### 테스트

```bash
uv run pytest        # TestClient로 입력 검증, 오류 처리, HTTP부터 도구 실행까지의 통합 흐름을 검증한다
```

### 한계

- 인증, 호출 횟수 제한(rate limit)이 없다. 외부에 공개하려면 둘 다 필요하다.
- 질문마다 독립 실행이며 대화 기억이 없다.
- 요청 처리 중에는 LLM 응답을 기다리는 동안 스레드가 점유된다. 동시 요청이 많아지면 스레드 풀 크기가 한계가 된다.

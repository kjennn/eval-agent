# eval-agent

인사담당자가 자연어로 질문하면, LLM 에이전트가 필요한 도구를 스스로 골라 평가 데이터를 조회하고 근거와 함께 답하는 서비스. (Python + LangGraph + MCP)

> 예: "2025년 영업본부 B등급 비율이 왜 다른 본부보다 높아?"

## 왜 만드는가

이 프로젝트의 목적은 두 가지다.

1. **직접 만들어 보며 익히기**: Java/Spring 백엔드 개발자로서 실무 경험이 없는 Python, 그리고 LangGraph와 MCP로 AI 에이전트를 처음부터 끝까지 직접 구현해 본다.
2. **설계 이유까지 설명할 수 있는 포트폴리오**: 동작하는 코드뿐 아니라 "왜 이렇게 설계했는가"를 설명할 수 있도록, 각 단계의 설계 결정과 한계를 기록한다.

### 이전 프로젝트와의 차이

이전에 Spring AI로 평가 문의 자동 분류 시스템을 만들었다. 그 시스템은 **정해진 순서대로 도는 워크플로**였다. 이번에는 **LLM이 어떤 도구를 부를지 직접 선택하는 에이전트 구조**로 만들어, 두 방식의 차이를 직접 비교하고 설명할 수 있게 하는 것이 목표다.

## 설계 원칙

- **도구는 자유 SQL을 받지 않는다.** 정해진 파라미터만 받는 읽기 전용 함수로 만들어, LLM이 DB를 마음대로 조회하거나 변경할 수 없게 한다.
- **도구를 먼저 만들고 검증한 뒤 에이전트에 연결한다.** 도구는 순수 함수로 만들어 pytest로 검증한다.
- **도구로 확인한 숫자만 사실로 말한다.** 데이터에 없는 원인은 추측하지 않고 "추가 확인이 필요합니다"라고 답한다. 답변 끝에는 어떤 도구를 어떤 조건으로 호출했는지 근거를 붙인다.
- **개인 이름은 노출하지 않는다.** 집계 결과만 다룬다.
- **실제 고객사 데이터를 쓰지 않는다.** 모든 데이터는 시드 스크립트가 만드는 더미 데이터다.

## 진행 단계

| 단계 | 내용 | 상태 |
|------|------|------|
| 1 | 프로젝트 구조 + uv 환경 + docker-compose(PostgreSQL) | 완료 |

## 구조

```
                      ┌─────────────────────────────┐
  인사담당자 ───────→ │ CLI (scripts/ask.py)        │──┐
  (자연어 질문)       │ HTTP API (POST /ask)        │  │   질문
                      └─────────────────────────────┘  ▼
                                          ┌──────────────────────────┐
                                          │ LangGraph 에이전트        │
                                          │  LLM이 도구를 골라 호출   │──→ Claude API
                                          │  반복 한도, 근거 자동 첨부 │
                                          └────────────┬─────────────┘
                                                       │ 같은 도구 4개
  Claude Desktop / Claude Code ──(MCP, stdio)──────────┤
                                                       ▼
                                  ┌──────────────────────────────────────┐
                                  │ 도구 (읽기 전용, 고정 파라미터)        │
                                  │  get_grade_distribution compare_years │
                                  │  get_org_summary  search_policy_docs  │
                                  └──────┬───────────────────────┬───────┘
                                         ▼                       ▼
                                 PostgreSQL (더미 데이터)    docs/policy/*.md
```

같은 도구 4개를 두 가지 방식으로 쓸 수 있다.

- **에이전트 방식:** 우리 코드가 Claude API를 호출해서 도구 선택, 반복 한도, 답변 규칙, 근거 첨부를 통제한다.
- **MCP 방식:** Claude Desktop/Code가 우리 도구를 직접 쓴다. 우리 코드에는 LLM이 없다.

### 폴더 구성

```
src/eval_agent/
  models.py, seed_data.py     스키마(SQLAlchemy)와 더미 데이터 생성
  tools/                      도구 4개 (순수 함수) + 도구 설명 문구(descriptions.py)
  agent/                      LangGraph 그래프, 프롬프트, LLM 생성(factory.py)
  api/                        FastAPI 앱
  mcp_server/                 MCP 서버 (도구를 MCP 형식으로 노출하는 얇은 어댑터)
scripts/                      seed.py, ask.py(CLI), check_db.py
docs/policy/                  기준 문서(더미) 4개 - search_policy_docs의 검색 대상
tests/                        pytest 72개
```

Java/Spring로 비유하면 `tools/`는 서비스 계층이고, `agent/`(+`api/`)와 `mcp_server/`는 같은 서비스를 서로 다른 방식으로 노출하는 진입점(컨트롤러)이다.

## 핵심 설계 결정

| 결정 | 이유 |
|------|------|
| 도구는 자유 SQL 없이 고정 파라미터의 읽기 전용 함수 | LLM이 DB를 마음대로 조회하거나 바꾸지 못하게 하고, 입력과 출력이 정해져 있어 pytest로 검증할 수 있다. |
| 도구를 먼저 만들고 검증한 뒤 에이전트에 연결 | LLM 없이 도구만으로 숫자의 정확성을 확인할 수 있다. 에이전트가 틀리면 원인이 도구인지 LLM인지 가려낼 수 있다. |
| 비율 변화(%p)를 코드가 건수로 계산 | LLM이나 반올림된 비율로 계산하면 오차가 난다(실제로 16.6이 나와 16.7로 고쳤다). 계산은 코드가, 해석은 LLM이 한다. |
| 근거 문구는 LLM이 아니라 코드가 호출 기록에서 뽑아 붙임 | LLM은 부르지 않은 도구를 불렀다고 쓰거나 조건을 틀리게 쓸 수 있다. |
| 데이터 없음을 예외가 아닌 `{"error": "no_data", "available_years": [...]}` 결과로 반환 | LLM이 읽고 "2023년은 없고 2024·2025만 있다"고 답할 수 있다. 에이전트와 MCP가 같은 방식을 쓴다. |
| 반복 한도를 그래프 안에서 처리 | 한도에 닿아도 예외로 죽지 않고 "추가 확인이 필요합니다"와 지금까지의 호출 기록을 돌려준다. |
| LLM을 밖에서 주입 | 테스트에서 가짜 LLM으로 그래프 배선, 한도, 근거 첨부를 비용 없이 검증한다. |
| 도구 설명을 한 파일로 공유 | 에이전트와 MCP 설명이 어긋나지 않는다. 테스트가 같은지 검사한다. |
| 개인 이름 없이 집계만 반환 | 테스트가 결과에 직원 이름이 없는지 검사한다. |
| API는 `def`, 에이전트는 서버 시작 때 한 번 생성 | 동기 코드를 `async def`에서 부르면 이벤트 루프가 막힌다. 요청마다 만들면 DB 풀과 LLM 클라이언트가 낭비된다. |

각 단계의 상세 결정은 아래 단계별 섹션에 있다.

## 검증 현황

실제로 확인한 것과 하지 못한 것을 구분해 적는다.

**확인한 것**
- `uv run pytest` 72개 통과 (가짜 LLM, 메모리 SQLite, 인메모리/실제 stdio MCP 클라이언트 사용. API 호출·비용 없음)
- 실제 Claude API로 CLI와 `POST /ask`를 호출해 테스트 질문의 답변과 근거 첨부를 확인했다.
- 임시 PostgreSQL에 시드를 넣고 MCP 서버를 실제 stdio로 띄워 테스트 질문 5개에 쓰이는 도구 호출을 확인했다.
- Claude Desktop에 MCP 서버를 연결해 새 대화에서 질문했고, 도구를 사용해 답하는 것을 확인했다.

**실제 개발 중 발견해 고친 문제**
- 일부 최신 모델이 `temperature` 파라미터를 거절(400)해서 제거했다. 가짜 LLM 테스트로는 발견할 수 없었고 실제 호출에서 드러났다.
- 답변이 `max_tokens`에서 문장 중간에 잘려서 한도를 설정 가능하게 하고, 잘리면 안내를 붙이도록 했다.
- Claude Desktop 설정에서 `mcpServers`를 `preferences` 안쪽에 넣으면 조용히 무시된다. 최상위 키여야 한다(아래 6단계 참고).

**확인하지 못한 것**
- 답변 품질의 체계적 평가(테스트 질문 5개 외의 다양한 질문, 답변의 정확도 측정)는 하지 않았다.
- LLM 응답은 매번 표현이 다를 수 있다. 같은 질문의 반복 실행 안정성은 측정하지 않았다.

## 한계와 다음 단계

**한계**
- 인증과 호출 횟수 제한이 없다. API는 호출마다 Claude API 비용이 들기 때문에 외부에 공개하면 안 된다.
- 질문마다 독립 실행이며 대화 기억이 없다("그럼 개발본부는?" 같은 후속 질문을 이해하지 못한다).
- 기준 문서 검색은 키워드 매칭이다. 표현이 다르면(동의어, 조사 차이) 놓칠 수 있다.
- DB 계정이 읽기 전용으로 분리돼 있지 않다. 도구가 읽기 전용 함수라 안전하지만, 운영이라면 계정 수준에서도 막는 것이 맞다.
- MCP 방식은 우리의 답변 규칙(근거 자동 첨부, "추가 확인이 필요합니다")이 적용되지 않는다. 클라이언트의 Claude가 도구 설명만 보고 답한다.
- 데이터는 더미이고 규모가 작다(250명, 2개 연도). 실제 규모의 성능은 검증하지 않았다.
- 동기 에이전트라 동시 요청이 많으면 스레드 풀이 한계가 된다.

**다음에 해볼 수 있는 것**
- 대화 기억(LangGraph 체크포인터)으로 후속 질문 지원
- 기준 문서 검색을 임베딩 기반으로 교체하고, 키워드 검색과 품질 비교
- 답변 품질 평가 세트(질문과 기대 도구 호출·숫자)를 만들어 자동 채점
- 응답 스트리밍, 호출 횟수 제한과 인증
- 읽기 전용 DB 계정 분리, MCP 서버의 원격(HTTP) 전환과 인증

## 1단계: 환경 준비

내 PC에서 DB와 파이썬 환경이 정상적으로 갖춰졌는지 확인하는 절차다.

```bash
cp .env.example .env                       # 설정 파일 생성 (.env는 커밋되지 않음)
docker compose up -d                       # PostgreSQL 컨테이너 기동
uv sync                                    # Python 3.12 가상환경 + 의존성 설치
uv run python scripts/check_db.py          # DB 접속 확인
uv run pytest                              # 테스트 실행
```

| 명령 | 하는 일 |
|------|---------|
| `cp .env.example .env` | 견본(`.env.example`)으로 실제 설정 파일을 만든다. DB 접속 정보와 API 키 같은 비밀값을 여기에 둔다. |
| `docker compose up -d` | `docker-compose.yml`대로 PostgreSQL 16 컨테이너를 백그라운드로 띄운다. 데이터는 Docker 볼륨에 저장되어 컨테이너를 껐다 켜도 남는다. |
| `uv sync` | `pyproject.toml`과 `uv.lock`대로 프로젝트 전용 가상환경(`.venv`)을 만들고 라이브러리를 설치한다. Python 3.12가 없으면 uv가 받아 온다. |
| `uv run python scripts/check_db.py` | `.env`의 `DATABASE_URL`로 DB에 접속해 `SELECT version()`을 실행한다. `DB 연결 성공: PostgreSQL 16...`이 나오면 정상이다. |
| `uv run pytest` | `tests/` 아래 테스트를 모두 실행한다. |

Docker 데몬이 꺼져 있으면 `Cannot connect to the Docker daemon` 오류가 난다. Docker Desktop을 먼저 실행한다.

## 2단계: 스키마 + 더미 데이터

```bash
uv run python scripts/seed.py            # 테이블 생성 + 더미 데이터 입력 (이미 있으면 중단)
uv run python scripts/seed.py --reset    # 전체 삭제 후 재생성 ('yes' 입력 필요)
```

- 모든 데이터는 가짜이며, 같은 seed로 항상 같은 결과가 나온다.
- 영업본부는 2025년 B등급 비율이 약 68%로 일부러 높게 만들었다.

## 3단계: 도구 4개

모든 도구는 정해진 파라미터만 받는 읽기 전용 함수이고, 개인 이름 없이 집계만 돌려준다. 조회가 안 되면 예외 대신 `{"error": ...}`를 돌려줘서 LLM이 "데이터가 없다"고 답할 수 있게 한다.

| 도구 | 파라미터 | 결과 |
|------|----------|------|
| `get_grade_distribution` | year, org_name?, eval_type? | 등급별 인원·비율, 하위 조직별 breakdown |
| `compare_years` | org_name, year_from, year_to | 두 연도 분포와 등급별 변화(%p) |
| `get_org_summary` | year, org_name | 인원수, 평균 점수, 평가유형별 평균 |
| `search_policy_docs` | query, top_k? | 기준 문서에서 관련 문단 (키워드 검색) |

```bash
uv run pytest        # DB 없이 메모리 SQLite로 도구를 검증한다
```

## 4단계: LangGraph 에이전트 + CLI

LLM이 3단계 도구 중 필요한 것을 스스로 골라 호출하고, 결과를 보고 다시 판단해서 최종 답변을 만든다.

### 준비

`.env`에 발급받은 API 키와 모델명을 넣는다. (`.env`는 커밋되지 않는다. 키를 `.env.example`이나 코드에 넣지 않는다.)

```
ANTHROPIC_API_KEY=발급받은_키
ANTHROPIC_MODEL=claude-haiku-5-5      # 개발 중에는 저렴한 모델로 시작
AGENT_MAX_ITERATIONS=6                # 도구 호출 반복 상한 (무한 루프·비용 폭주 방지)
AGENT_MAX_TOKENS=2048                 # LLM 답변 한 번의 최대 길이 (너무 작으면 답변이 잘린다)
```

### 실행

```bash
uv run python scripts/ask.py "2025년 본부별 B등급 비율을 비교해줘"
uv run python scripts/ask.py -v "개발본부 다면평가 평균은?"    # -v: 도구 호출과 결과를 단계별로 출력
uv run python scripts/ask.py                                    # 질문 없이 실행하면 대화형
```

질문마다 독립적으로 실행되며 이전 질문을 기억하지 않는다.

### 그래프 흐름

```
                 ┌──────────── 도구 호출 요청 있음 & 한도 미만 ───────────┐
                 ▼                                                        │
    START → [agent] ──┬── 도구 호출 요청 없음 ──→ [finalize] → END         │
                      ├── 도구 호출 요청 있음 & 한도 도달 → [limit] → END   │
                      └───────────────→ [tools] ───────────────────────────┘
```

- `agent`: LLM을 한 번 호출한다. LLM은 도구 호출을 요청하거나 최종 답변을 한다.
- `tools`: 요청된 도구를 실행하고 결과를 상태에 쌓는다.
- `finalize`: 최종 답변 뒤에 **실제 호출 기록에서 뽑은 근거**(어떤 도구를 어떤 조건으로 불렀는지)를 코드로 붙인다.
- `limit`: 반복 한도에 도달하면 "추가 확인이 필요합니다"와 함께 멈춘다.

### 설계 결정

- **근거는 LLM이 아니라 코드가 붙인다.** LLM은 호출하지 않은 도구를 호출했다고 쓰거나 조건을 틀리게 쓸 수 있다. 호출 기록에서 뽑으면 사실만 남는다.
- **반복 한도는 그래프 안에서 처리한다.** 한도에 도달하면 예외로 죽지 않고 안내 문구와 지금까지의 호출 기록을 돌려준다.
- **LLM을 밖에서 주입한다.** `build_graph(llm, ...)`가 LLM을 인자로 받아서, 테스트에서는 정해진 응답을 내는 가짜 LLM으로 그래프 배선을 검증한다.
- **조회 가능한 연도는 프롬프트에 DB 값을 넣는다.** "작년", "올해" 같은 상대 표현을 코드에 박힌 연도 없이 해석하게 한다.
- **`AGENT_MAX_TOKENS`로 답변 길이(비용) 상한을 둔다.** 처음에 1024로 두었더니 기준 문서와 데이터를 함께 설명하는 긴 답변이 문장 중간에 잘렸다. 기본값을 2048로 올리고, 프롬프트에서 간결하게 쓰도록 하고, 그래도 잘리면 `stop_reason`을 보고 답변에 "잘렸습니다" 안내를 붙인다.
- **`temperature`는 보내지 않는다.** 일부 최신 모델이 이 파라미터를 거절해서(400 오류) 제거했다. 그래서 같은 질문에도 답변 표현이 달라질 수 있다.

### 테스트

```bash
uv run pytest        # 가짜 LLM으로 그래프 흐름·반복 한도·근거 첨부를 검증한다 (API 호출 없음, 비용 없음)
```

가짜 LLM으로는 그래프의 배선만 검증할 수 있다. 실제 Claude가 도구를 알맞게 고르는지, 답변 규칙을 지키는지는 CLI로 테스트 질문을 던져 확인한다.

## 5단계: FastAPI `POST /ask`

에이전트를 HTTP API로 감싼다. 서버가 시작될 때 에이전트(LLM 클라이언트, DB 연결 풀, 컴파일된 그래프)를 한 번만 만들고 요청마다 재사용한다.

### 실행

```bash
uv run uvicorn eval_agent.api.app:app --host 127.0.0.1 --port 8000
```

- API 문서(Swagger UI): http://127.0.0.1:8000/docs
- 주의: 이 API는 호출할 때마다 Claude API 비용이 든다. **인증이 없으므로 외부에 공개하지 않는다.** 기본 설정(127.0.0.1)은 내 PC에서만 접속된다.

### 호출 예시

```bash
curl -s -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "개발본부 다면평가 평균은?"}'
```

응답:

```json
{
  "answer": "개발본부 2025년 다면평가 평균은 76.66점입니다. ...\n\n근거(호출한 도구와 조건):\n- get_org_summary(year=2025, org_name='개발본부')",
  "tool_calls": [
    {"name": "get_org_summary", "args": {"year": 2025, "org_name": "개발본부"}, "error": null}
  ],
  "iterations": 2
}
```

| 엔드포인트 | 설명 |
|------------|------|
| `POST /ask` | 질문(1~500자)을 받아 답변, 도구 호출 목록, LLM 호출 횟수를 돌려준다. |
| `GET /health` | 서버 상태 확인 |

| 상태 코드 | 의미 |
|-----------|------|
| 200 | 정상 |
| 422 | 입력 오류 (질문 없음, 공백뿐, 500자 초과). LLM을 호출하지 않는다. |
| 502 | LLM 호출 실패. 원인(API 키 오류 등)은 서버 로그에만 남고 응답에는 노출하지 않는다. |

### 설계 결정

- **에이전트는 서버 시작 때 한 번 만든다.** 요청마다 만들면 DB 연결 풀과 LLM 클라이언트를 매번 새로 만들게 된다. 설정이 잘못됐으면(API 키 없음 등) 요청이 들어온 뒤가 아니라 서버 시작 단계에서 바로 실패한다.
- **엔드포인트는 `async def`가 아니라 `def`로 만든다.** 에이전트가 동기(블로킹) 코드라서, `async def` 안에서 호출하면 이벤트 루프가 막혀 서버 전체가 그동안 멈춘다. `def`면 FastAPI가 스레드 풀에서 실행한다.
- **입력 길이에 상한(500자)을 둔다.** 호출마다 비용이 드는 API이므로 비용이 큰 입력을 앞단에서 막는다.
- **오류 원인은 응답에 노출하지 않는다.** 내부 예외 메시지에는 API 키 오류나 내부 구조가 담길 수 있어서 로그에만 남긴다.
- **`create_app(agent=...)`로 에이전트를 주입할 수 있다.** 테스트에서는 가짜 에이전트나 가짜 LLM을 꽂는다.

### 테스트

```bash
uv run pytest        # TestClient로 입력 검증, 오류 처리, HTTP부터 도구 실행까지의 통합 흐름을 검증한다
```

### 한계

- 인증, 호출 횟수 제한(rate limit)이 없다. 외부에 공개하려면 둘 다 필요하다.
- 질문마다 독립 실행이며 대화 기억이 없다.
- 요청 처리 중에는 LLM 응답을 기다리는 동안 스레드가 점유된다. 동시 요청이 많아지면 스레드 풀 크기가 한계가 된다.

## 6단계: MCP 서버

3단계의 도구 4개를 MCP(Model Context Protocol) 서버로 노출한다. Claude Desktop이나 Claude Code가 에이전트(4~5단계) 없이 이 도구를 직접 쓸 수 있다.

### 에이전트와 MCP 서버의 차이

| | 에이전트 (4~5단계) | MCP 서버 (6단계) |
|---|---|---|
| LLM이 있는 곳 | 우리 서버 (Claude API를 우리가 호출) | Claude Desktop/Code 쪽 |
| 우리가 제공하는 것 | 질문 → 최종 답변 | 도구 목록과 도구 실행 |
| Claude API 키·비용 | 필요 (우리 계정) | 필요 없음 |
| 반복 한도, 답변 규칙 프롬프트 | 우리가 관리 | 클라이언트(Claude)가 관리 |

같은 도구 로직(3단계)을 두 방식이 공유하고, 도구 설명 문구도 `tools/descriptions.py` 한 곳에서 가져온다.

### 실행과 연결

서버는 stdio 방식이다. Claude Desktop/Code가 이 프로세스를 직접 실행하고 표준 입출력으로 통신한다. 네트워크 포트를 열지 않아서 내 PC 밖에서는 접속할 수 없다. DB(`docker compose up -d`)는 켜져 있어야 한다.

직접 실행해 보기(연결 없이 서버가 뜨는지만 확인, 종료는 Ctrl+C):

```bash
uv run python -m eval_agent.mcp_server
```

**Claude Desktop** — 설정 파일(macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`, 앱의 Settings → Developer → Edit Config로도 열린다)에 추가한다. 경로는 모두 절대 경로로 쓴다. `command`는 `which uv`로 나온 절대 경로를 권장한다(앱이 터미널과 다른 PATH로 실행될 수 있다).

```json
{
  "mcpServers": {
    "eval-agent": {
      "command": "/절대/경로/uv",
      "args": ["--directory", "/Users/내이름/workspace/eval-agent", "run", "python", "-m", "eval_agent.mcp_server"]
    }
  }
}
```

설정 파일에 이미 `preferences` 같은 다른 항목이 있으면, `mcpServers`를 그 **안쪽이 아니라 같은 최상위 수준**에 쉼표로 이어 붙인다. 안쪽에 넣어도 JSON 문법은 맞아서 오류 없이 조용히 무시되고, 로그도 남지 않는다. 수정 후 `python3 -m json.tool <설정파일>`로 문법을 확인한다.

저장한 뒤 Claude Desktop을 완전히 종료(Cmd+Q)했다가 다시 실행한다. Settings → Developer에 `eval-agent`가 `running`으로 보이면 연결된 것이다. 로그는 `~/Library/Logs/Claude/mcp*.log`에서 볼 수 있다.

**Claude Code**

```bash
claude mcp add --transport stdio eval-agent -- /절대/경로/uv --directory /Users/내이름/workspace/eval-agent run python -m eval_agent.mcp_server
claude mcp list        # ✔ Connected 이면 연결됨
```

Claude Code 안에서는 `/mcp`로 서버 상태와 도구 개수를 볼 수 있다.

연결한 뒤에는 "2025년 본부별 B등급 비율을 비교해줘" 같은 질문을 하면, Claude가 이 서버의 도구를 골라 호출한다.

### 설계 결정

- **도구 로직은 그대로 두고 얇은 어댑터만 더한다.** `get_grade_distribution` 등 3단계 함수는 건드리지 않고, `mcp_server/server.py`가 세션을 열어 호출한 뒤 결과 dict를 돌려준다.
- **도구 설명은 에이전트와 MCP가 공유한다.** 한쪽만 고쳐서 두 곳의 동작이 어긋나는 일을 막고, 테스트가 두 설명이 같은지 검사한다.
- **데이터 없음은 오류가 아니라 안내 결과로 돌려준다.** 에이전트와 같은 방식이라, 클라이언트의 LLM이 "조회 가능한 연도"를 읽고 스스로 복구할 수 있다. 반면 필수 인자 누락이나 타입 오류는 MCP의 오류 응답(`is_error`)으로 거절된다.
- **stdout은 프로토콜 전용이다.** 서버 코드에서 `print()`를 쓰면 메시지가 깨져 연결이 끊긴다. 실제 프로세스를 띄워 통신하는 테스트가 이를 지킨다.
- **SDK 이름 변경:** mcp 2.x에서는 `FastMCP`가 `MCPServer`로 바뀌었다. 이 프로젝트는 2.x(`from mcp.server.mcpserver import MCPServer`)를 쓴다.

### 테스트

```bash
uv run pytest        # 인메모리 클라이언트 + 실제 stdio 프로세스로 도구 목록, 호출 결과, 오류 처리를 검증한다
```

### 한계

- 서버가 DB에 쓰는 계정을 따로 제한하지 않는다. 도구가 읽기 전용 함수라서 안전하지만, 운영 환경이라면 DB 계정 자체를 읽기 전용으로 분리하는 것이 안전하다.
- 인증이 없다. stdio 방식이라 로컬 프로세스 간 통신에 한정되고, 원격(HTTP)으로 공개하려면 인증이 필요하다.
- 데이터는 더미 데이터이고 실제 고객사 데이터를 연결하지 않았다.
